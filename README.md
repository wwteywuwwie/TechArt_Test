Тестовое задание на позицию Technical Artist. Персонаж от третьего лица наносит удары мечом по мишени и получает мгновенную визуальную и пространственную обратную связь.

* **Версия Unity:** 6000.3.5f1 
* **Сцена:** Assets/Project/Scenes/Arena.unity
* **Репозиторий:** [https://github.com/wwteywuwwie/TechArt_Test](https://github.com/wwteywuwwie/TechArt_Test)

## 1. Управление и точный сценарий воспроизведения

### 1.1. Клавиши управления

| Действие | Клавиша |
| --- | --- |
| Перемещение | WASD |
| Вращение камеры | Мышь |
| Прыжок / Спринт | Space |
| Удар мечом | ЛКМ |
| Замер производительности (30 секунд) | F9 |

### 1.2. Сценарий воспроизведения

1. **Фаза покоя:** Герой подходит к тренировочной мишени (щит на бревенчатой стойке). Мишень находится в состоянии **«Готова»**.
2. **Замах и Trail:** По нажатию ЛКМ запускается замах клинка. Активируется TrailRenderer на лезвии меча. Трейл отрисовывается исключительно во время активной фазы удара, исключая визуальный шум в покое.
3. **Момент контакта:**
   * Клинок пересекает коллайдер мишени: попадание регистрируется через Physics.OverlapCapsuleNonAlloc (слой Target).
   * **Hit Pause (хит-стоп):** клинок процедурно замирает на **0.06 с**, придавая оружию ощущение массы и плотности контакта.
   * **Вспышка и искры:** из пула ImpactVfxPool берется эффект VFX_Impact (комбинация яркой короткой вспышки Flash и снопа вторичных искр Sparks, ориентированных по нормали контакта).
   * **Dynamic Point Light:** точечный источник света в точке удара вспыхивает на **0.08 с** (800 lm, без теней), подсвечивая клинок, манекен и землю.
4. **Реакция мишени и материала:**
   * **Kinematic:** цельная мишень (Target_Training) отклоняется в сторону импульса с последующим затухающим покачиванием. Разрушаемая мишень (Target_Shatter) динамически раскалывается на обломки.
   * **Реакция материала (SG_TargetOverlay):** в точке удара в локальных координатах мгновенно проявляется выжженное пятно с пылающей кромкой. Параметры передаются через MaterialPropertyBlock без создания копий материалов.
5. **Фаза восстановления:**
   * В течение 4 секунд выжженное пятно плавно сжимается к центру.
   * Горящая кромка остывает по температурному градиенту.
   * Мишень возвращается в исходное состояние **«Готова»** (у Target_Shatter обломки кинематически притягиваются и собираются в исходную модель).
6. **Повторный удар:** в любой момент клинок может нанести новый удар - эффект корректно перезапускается в новой пространственной точке касания.

### 1.3. Покрытие требований ТЗ

| Требование ТЗ | Реализация в проекте | Проверка качества |
|---|---|---|
| **След (contact cue)** | TrailRenderer на клинке меча | Активен только в фазе удара; четкая траектория без остаточных артефактов |
| **Вспышка контакта** | VFX_Impact (партикл Flash) | Время жизни 0.05 с, привязано к реальной нормали контакта |
| **Вторичные частицы** | VFX_Impact (партикл Sparks) |искры с физическим разлетом и затуханием гравитацией |
| **Реакция материала** | Шейдер SG_TargetOverlay | Выжженное пятно с кромкой и локальным растворением |
| **Dynamic light события** | Realtime Point Light в VFX_Impact | 800 lm, 0.08 с, тени отключены для нулевого оверхеда по Shadow Map |
| **3 состояния мишени** | Скрипты TargetKnockback и TargetBreakApart | Визуальная разница: геометрия + кинематика + температура оверлея |

## 2. Архитектура интеграции

### 2.1. Иерархия сцены (Assets/Project/Scenes/Arena.unity)

* **[Environment]**
  * **Floor:** плоскость пола арены, материал мокрого грунта с процедурными лужами (SG_WetGround).
  * **Environment_Walls:** бревенчатый частокол по периметру, определяющий границы боевой зоны.
  * **Props_Environment:** палатки, навесы, скамьи и элементы окружения лагеря.
  * **Props_Torches:** настенные факелы с локальными источниками теплого освещения.
  * **Props_Weapons / Racks:** стойки с оружием и реквизит.
  * **Targets (Target_Training / Target_Shatter):** тренировочные мишени (цельные с качанием и разрушаемые с физическим разлетом).
* **[Lighting]**
  * **Directional_Sun:** ключевое предзакатное солнце (Mixed, 1200 Lux, Kelvin 4000, тени Custom 512).
  * **Light_Fill:** заполняющий зенитный свет (Realtime Directional, 1100 Lux, Kelvin 9000, без теней).
  * **Light_Rim:** контурный свет персонажа (Realtime Directional, 500 Lux, Kelvin 6570, без теней).
  * **APV_Arena:** запеченная сетка Adaptive Probe Volume (глобальный режим для игровой зоны).
  * **ReflectionProbe_Arena:** запеченная локальная Reflection Probe (режим Baked, бокс 30×8×30 м).
  * **GlobalVolume_Twilight:** профиль атмосферы, экспозиции, тональной компрессии, SSAO, Contact Shadows и Bloom.
  * **Fog:** локальный объемный туман (Local Volumetric Fog) с текстурным шумом (3d_fractal_noise_sample01) для сумеречной атмосферы.
* **[Gameplay]**
  * **PerfLogger:** компонент автоматического сбора метрик производительности (F9).


### 2.2. Ключевые скрипты (Assets/Project/Scripts)

| Скрипт | Назначение и инженерные решения |
|---|---|
| **PlayerStrike.cs** | Процедурный замах клинка. Определение попадания через Physics.OverlapCapsuleNonAlloc с выделенным буфером (0 байт GC Alloc). Вычисляет точную мировую точку касания и нормаль, вызывает хит-стоп (0.06 с) и триггерит события. |
| **TargetFeedback.cs** | Управление состояниями мишени (Ready, Hit, Recover). Рассчитывает локальные координаты удара для каждой части модели с учетом ее Scale и передает свойства в шейдер через MaterialPropertyBlock (без инстанцирования материалов). |
| **TargetReaction.cs** | Абстрактный базовый класс для модульного расширения реакций мишеней. |
| **TargetKnockback.cs** | Реакция цельных манекенов: расчет вектора отдачи от направления атаки героя, плавное отклонение за 0.12 с и затухающие колебания маятника с коэффициентом демпфирования. |
| **TargetBreakApart.cs** | Реакция разрушаемых мишеней: кинематический разлет составных кусков с интерполяцией по кривой без тяжелых физических Rigidbody; выдержка 1 с и поочередная обратная сборка (снизу вверх) за 3 с. |
| **ImpactVfxPool.cs** | Реализация паттерна Object Pool: инициализирует фиксированный пул префабов VFX_Impact при старте сцены, исключая Instantiate / Destroy и скачки GC в ходе боя. |
| **ImpactFlash.cs** | Контроллер точечного света удара: экспоненциальное затухание яркости Point Light за 0.08 с с автоматическим возвратом объекта в пул. |
| **PerfLogger.cs** | Инструмент точного профилирования: 30-секундный буфер замера времени кадров по клавише F9. Вычисляет Median FPS, Mean FPS, 1% Low, Min FPS, вызовы GC и дельту используемой памяти (GC.GetTotalMemory). |

### 2.3. Таблица состояний мишеней

| Тип мишени | Состояние «Готова» | Состояние «Получила попадание» | Состояние «Восстановление» |
|---|---|---|---|
| **Target_Training** (щит на стойке) | Стоит строго вертикально; поверхность чистая, альфа оверлея = 0 | Мгновенное отклонение от удара (угол 75°); яркое выжженное пятно в точке контакта с пылающей кромкой (2.5) | с затухающих колебаний; пятно стягивается к центру; кромка остывает в темно-красный и угасает |
| **Target_Shatter** (щит на стойке) | Стоит строго вертикально; поверхность чистая, альфа оверлея = 0  | Разлет обломков по радиусу; на задетом фрагменте пылает рваный след удара с интенсивной тлеющей эмиссией  | Обломки лежат 1 с, затем кинематически притягиваются обратно (нижние фрагменты первыми); пятно остывает |

### 2.4. Архитектурное решение оверлея (SG_TargetOverlay)

Вместо замещения основного материала объекта, применен **Transparent Overlay**:
1. На каждой части мишени слот 0 содержит стандартный непрозрачный PBR-материал (дерево, ткань, металл).
2. Слот 1 содержит прозрачный шейдер SG_TargetOverlay.
3. TargetFeedback находит слот оверлея и передает параметры через единый MaterialPropertyBlock. Основной материал не затрагивается, клонирования материалов в памяти не происходит.

## 3. Shader Graph: параметры и пресеты

### 3.1. Параметризованный шейдер SG_TargetOverlay
* **Surface Type:** Transparent.
* **Выполненные признаки ТЗ:**
  1. *Маска растворения/проявления:* процедурный градиент расстояния от точки удара, модулированный шумом Simple Noise.
  2. *Управляемая эмиссия:* выделение контура границы растворения через Smoothstep с умножением на цвет кромки и коэффициент HDR-интенсивности.
  3. *Local/World-space модуляция:* вычисление расстояния от локальных координат вершины/пикселя до переданного вектора Hit Position с масштабированием по Hit Radius.

| Свойство шейдера | Тип в Unity | Значение по умолчанию | Физический и графический смысл |
|---|---|---|---|
| _DissolveAmount | Float (0 .. 1) | 0.0 | Степень раскрытия пятна (0 = оверлей полностью прозрачен, 1 = максимальный радиус) |
| _HitPosition | Vector3 | (0, 0, 0) | Точка удара в локальных координатах пораженного фрагмента |
| _HitRadius | Float | 0.85 | Базовый радиус распространения термического следа (метры) |
| _NoiseScale | Float | 35.0 | Частота процедурного шума, задающая рваную природную структуру обугливания |
| _EdgeWidth | Float (0.01 .. 0.25) | 0.08 | Ширина светящейся высокотемпературной кромки фронта горения |
| _EdgeColor | Color (HDR) | #FFA633 (1.5, 0.7, 0.1) | Спектральный оттенок раскаленного края |
| _EmissionIntensity | Float | 1500 | Множитель яркости свечения для корректной передачи энергии в Bloom HDRP |
| _CharredColor | Color | #1A1512 | Базовый цвет обугленного центра пятна |
| _NormalOffset | Float | 0.003 | Величина смещения вершин вдоль нормали для исключения Z-fighting |

### 3.2. Два визуально различимых пресета материала

| Пресет материала | Объект применения | Оттенок кромки | Edge Width | Noise Scale | Визуальный характер |
|---|---|---|---|---|---|
| **M_TargetOverlay_Fire** | Target_Training |  Tемно-красный  | 0.08 | 25.0 |  Рваный контур и ярко красным контуром. |
| **M_TargetOverlay_Ember** | Target_Shatter | Теплый оранжево-золотой| 0.12 | 35.0 |чистый разрез с золотым свечением и ровным обожженным контуром. |

### 3.3. Шейдер влажного грунта SG_WetGround

 №1 ТЗ («минимум один отражающий/влажный материал») разработан Lit-шейдер двора:
* Базовый слой: PBR-текстуры грунта Ground048 
* В зонах скопления влаги Smoothness возрастает до 0.75, Albedo затемняется множителем 0.75 (физический эффект намокания пористой земли), а карта нормалей интерполируется в гладкую поверхность воды с легкой рябью (Water_Ripple). В результате в лужах четко читаются зеркальные отражения сумеречного неба, факелов и вспышек боя.

### 4.2. Настройки Global Volume


### 4.2. Настройки Global Volume

- **HDRI Sky:** текстура SunsetSkyboxHDR (Exposure Compensation = 7.5, Rotation = 93°) - сумеречный фон с выраженным закатным градиентом.
- **Exposure:** Fixed Exposure (EV = 8.0) - фиксированная экспозиция без динамической адаптации глаза камеры при вспышках удара.
- **Bloom:** Intensity = 0.103, Scatter = 0.7, Tier = Medium - аккуратное свечение HDR-кромок и искр без заливки кадра.
- **Fog & Volumetric Fog:** Volumetric Fog включен (Denoising = Gaussian, Tier = Medium, Fog Attenuation Distance = 400 м, Max Distance = 1000 м) для мягкой сумеречной воздушной перспективы.
- **Shadows & Cascades:** Max Distance = 50 м, 4 каскада (Split 1: 2.5 м, Split 2: 5.0 м, Split 3: 7.5 м, Max: 35.0 м) для высокой детализации теней вблизи героя.
- **Shadows, Midtones, Highlights:** тонкая цветокоррекция с незначительным сдвигом в Shadows (Y = -0.086) и Midtones (Y = 0.061) для проработки контраста.
- **Screen Space Ambient Occlusion (SSAO):** Intensity = 0.98, Radius = 2.22, Tier = Low, Step Count = 4 - глубокие затенения стыков без падения производительности.
- **Contact Shadows:** Length = 0.459, Opacity = 1.0, Tier = Medium, Sample Count = 10 - четкие контактные тени на мелких деталях персонажа и манекенов.
- **White Balance:** Temperature = -0.3 - легкая корректировка сумеречного тона.
- **Tonemapping:** ACES - кинематографичный цветовой охват с правильным сохранением деталей в пересвеченных зонах.

## 5. Производительность, профилирование и метрики

### 5.1. Конфигурация тестового стенда

* **Процессор:** Intel Core i3-10100F @ 3.60 GHz (4 ядра, 8 потоков)
* **Видеокарта:** NVIDIA GeForce GTX 1660 Ti (6 GB VRAM)
* **Оперативная память:** 16 GB DDR4
* **Операционная система:** Windows 11 Pro 64-bit
* **Разрешение экрана:** 1920 × 1080 (100% масштаб, VSync OFF)
* **Quality Preset:** HDRP Asset (High Fidelity с оптимизацией Volumetrics до Medium)
* **Графический API:** DirectX 12
* **Режим сборки:** Windows Standalone, x64 (Non-Development, VSync отключен программно)

### 5.2. Методология измерения

Замеры производились непосредственно в финальном Standalone-билде (вне редактора Unity). Встроенный профилировщик PerfLogger.cs по нажатию клавиши F9 в течение 30 секунд (1800+ кадров) фиксирует точное время каждого кадра через Time.realtimeSinceStartupAsDouble, после чего рассчитывает:
* Медианный FPS (наиболее показательная метрика стабильности, не подверженная разовым системным выбросам).
* Средний FPS (Average).
* 1% Low FPS (показатель микрофризов и стабильности плавности).
* Минимальный зафиксированный FPS.
* Количество срабатываний Garbage Collector (GC).
* Изменение аллоцированной управляемой памяти (GC.GetTotalMemory).

### 5.3. Сводная таблица результатов (30 секунд на сценарий)

| Сценарий тестирования | Median FPS | Avg FPS | 1% Low FPS | Min FPS | Сборки GC | Δ Памяти (RAM) |
|---|---|---|---|---|---|---|
| **Baseline:** перемещение и спринт по арене без боевых действий | **120** | 119| 106| 100| 2 | -0.1 МБ |
| **Gameplay:** обычный бой с перебежками и ударами раз в 2–3 секунды | **121** | 121| 113| 94| 2 | -0.2 МБ |
| **Stress:** непрерывный спам ударов по мишеням (максимальный VFX/свет) | **118** | 118| 111| 98| 2 | -0.2 МБ |

> **Заключение:**
> Требование ТЗ (медиана не ниже 60 FPS при 1920×1080 при отключенном VSync) перевыполнено почти в 2 раза (~118–121 FPS при реальной нагрузке в билде).
Дельта медианного FPS между пассивным бегом и стресс-тестом составляет всего 2 кадра, что доказывает стабильность и независимость боевых систем от просадок фреймрейта.
Утечки памяти отсутствуют, GC работает стабильно, аллокации в боевом цикле сведены к минимуму.

## 6. Примененные оптимизации и известные ограничения

### 6.1. Примененные оптимизации

1. **Object Pooling (ImpactVfxPool):** полное исключение вызовов Instantiate / Destroy в игровом цикле. Все частицы, декали и световые вспышки берутся из предзагруженного кольцевого пула.
2. **Безаллокационная физика (Physics.OverlapCapsuleNonAlloc):** контакт оружия проверяется с предвыделенным массивом Collider[], что гарантирует 0 байт мусора на каждый удар.
3. **Кэширование идентификаторов и свойств:** все обращения к шейдерам выполняются через предварительно вычисленные Shader.PropertyToID, а корутины переиспользуют кэшированные объекты WaitForSeconds.
4. **Материальные блоки (MaterialPropertyBlock):** передача координат и радиуса поражения в шейдер не вызывает создания скрытых копий материалов (renderer.material), сохраняя память и SRP-состояние.
5. **Смешанная модель света:** тени рассчитываются исключительно для ключевого солнца; на вспомогательных источниках (Fill, Rim, Impact Point Light) расчет теней отключен, что снизило количество теневых проходов с 5 до 1 на кадр.
6. **Оптимизация HDRP Volumetrics:** перевод качества Volumetric Clouds и Volumetric Fog с пресета High на Medium дал прирост производительности с 78 до 130 FPS без визуально заметной потери художественного качества сцены.
7. **Отсутствие тяжелых декалей:** локальное термическое поражение вычисляется внутри шейдера оверлея, устраняя необходимость в DecalProjector с их дополнительными Draw Calls и затратами на буфер глубин.

### 6.2. Известные ограничения и архитектурные компромиссы

1. **Оверлей против прорезания геометрии:** материал SG_TargetOverlay накладывает термический след поверх меша и не делает сквозных геометрических отверстий (в отличие от boolean/CSG или alpha-clip на основном материале).
   * *Компромисс:* выбран ради 100% совместимости с любыми сторонними материалами и нулевого влияния на базовый PBR-пайплайн.
2. **Один дополнительный проход (Draw Call) на часть мишени:** прозрачный оверлей рендерится вторым сабмеш-пассом.
   * *Компромисс:* оверхед нивелирован малым количеством поражаемых целей (3–5 объектов в кадре).
3. **Предупреждение инспектора Unity:** при назначении оверлея вторым слотом на одномешевую модель Unity выводит предупреждение о несоответствии числа материалов числу сабмешей. На рендеринг и билд это не влияет и является штатным приемом для Transparent Pass в Unity.
4. **Процедурная кинематика разлета (TargetBreakApart):** обломки мишени разлетаются по расчетным векторным кривым без физических компонентов Rigidbody.
   * *Компромисс:* гарантирует 100% детерминированность, отсутствие физических коллизий между обломками и нулевые затраты на физический движок PhysX.

### 6.3. Статус консоли

* **Ошибки (Errors):** 0
* **Предупреждения (Warnings):** 0 в релизном Standalone-билде.
